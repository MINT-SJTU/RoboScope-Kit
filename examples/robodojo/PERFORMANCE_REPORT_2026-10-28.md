# RoboDojo 加速尝试汇总

本报告汇总 [suica/evostudio-evaluation-kit#31](https://github.com/suica/evostudio-evaluation-kit/pull/31) 的 recipe、runtime patch、并行评测和未通过的候选，关联 [#10](https://github.com/suica/evostudio-evaluation-kit/issues/10) / [#11](https://github.com/suica/evostudio-evaluation-kit/issues/11)（均为 suica/evostudio-evaluation-kit）。报告中的全部数值在 roboscope-kit 前身 EvoStudio SDK `3ee774a` 上测得；移植到 roboscope-kit 后 recipe 改为固定 roboscope-kit `2792b6e` 的 `two-phase` autotune，尚未在新 pin 上重新跑 GPU 实验。当前有完整 50 局并行对照，但还没有成功率无退化的稳定 runtime 加速结论。异步观察默认关闭；后续三布局 FIFO 短测不覆盖此前 50 局的成功率风险，不据此关闭 suica/evostudio-evaluation-kit#11。

## 固定范围与计时

官方 Simate-beta FP32 AE checkpoint，`stack_blocks / arx_x5 / seed 1`，完整范围为 layouts 0–49 各一次。模型预测 50 个动作、执行前 10 个，history 为 25 帧、间隔 20 动作，10 flow steps；physics dt=0.004 s、每动作 10 个物理子步、每局上限 550 动作。三路 RGB 和视频参数保持原设置。任务、源码、资产和权重版本固定在 [recipe.toml](recipe.toml)，不是 Meta-World 2500 局或 RoboDojo 全任务套件。

2026-10-29 根据已有记录补齐全程/正式两种口径和条件收益分析，未追加 GPU 实验。本报告没有 RoboDojo MPS 开关实验；不能把 Meta-World 的 MPS 数字或收益移入本任务。

主要性能实验使用 Isaac Sim 5.1.0.0、Python 3.11.15、Torch 2.7.0+cu128、驱动 580.105.08，GPU 为报告 49140 MiB 显存的 RTX 4090；不是普通 24 GiB 4090 的容量结论。物理运行在 CPU；容器 CPU 配额为 20 核，不能将 208 核 affinity 当作可用算力。

正式墙钟包含 episode reset、执行及窗口内视频处理；并行组取最早 worker 开始到最晚结束。实际 steps/s 使用真正执行的动作数，episodes/s 使用完整完成的局数。端到端另包含模型加载、仿真初始化、清理和存在时的 autotune 搜索；安装、下载、计时外完整视频解码不混入正式加速比。模型方法时间不是 GPU kernel 时间；worker 累计时间不能与并行墙钟直接相加。episodes/h = 完整完成局数 × 3600 / 对应墙钟秒数；steps/s = 实际策略步数 / 对应墙钟秒数，不能用 550×局数代替实际步数。吞吐倍率为 ON/OFF，同局数下等于 OFF 耗时/ON 耗时；减少耗时百分比与增加吞吐百分比不同。1 GiB=1024 MiB。资源使用设备 GPU 采样和容器 cgroup CPU/RAM，RAM 含缓存。缺失采样明确标缺失，不补造。

### RPC 和物理同步已定位到什么程度

后续原三布局的 cProfile 诊断，观察 RPC 累计 76.027 s，服务端模型锁等待 58.515 s，约占客户端阻塞 77%；每请求观察方法体仅 0.774 ms。执行器排队 0.269 s、返回事件循环 0.728 s，合计只占该组 execution 378.645 s 的 **0.26%**。因此重写执行器/唤醒路径不是大收益点。服务端 handle 累计 61.437 s，剩余约 14.590 s 尚混有传输、序列化、调度和跨边界测量差异，不能全部称作网络耗时或可回收开销。

FIFO10 的锁等待仍有 57.974 s；它让 worker 在等待时继续消费已预测动作，**隐藏阻塞，没有消除模型锁竞争**。模型方法仍共享锁；不允许去锁、跳过观察、改 history 或更改随机流来换取速度。单待办 50 局的成功率风险和 FIFO 的三局证据仍须分别看待。

同期三布局 physics_step 99.619 s；`fetch_results` self 80.886 s、累计 95.403 s，主要 Python USD 回调累计 8.022 s（已嵌套在同步内部）。simulate 与 fetch 各 13630 次，符合 1363 动作 × 10；每局 render/视频为 S+1。**没有发现重复 fetch 或多余的整次 render 可以直接删除。** `fetch_results` 同时覆盖物理等待、结果获取、USD 更新，Python profile 不能再区分其原生内部成本。已识别 USD 回调即使全部变为零，也仅相当于该三局 execution 的 2.12%，并不代表能省掉全部 95.403 s。

GPU 正式平均 60.89% 与单模型方法覆盖约 43% 并不矛盾：GPU 还做三路渲染，CPU 物理、模型锁和依赖链又留下空档。CPU 平均 8.226 核也不意味着剩余核可以直接补齐这些依赖。全程 GPU 均值 56.51% 还受到启动/清理的影响。目标应是同成功率、同工作量下更短的墙钟，不能以达到 Meta-World 的 80–90% 利用率作为验收条件。

### 后续修改建议与条件收益

以下是**根据占比做的条件测算，不是承诺或已测结果**。若某分项占 execution 的比例为 `f`，该分项耗时减少 `r`，等工作量下 execution 理想倍率为 `1 / (1 - f*r)`。这个公式只解释累计 execution；reset、模型竞争、worker 重叠和关键路径都会影响实际正式/全程收益，不能直接把结果换算为“50 局必定多少分钟”。各行也不能相乘。

| 部分 / 优先级 | 可以考虑的具体修改或检查 | 做到后的效果与边界 | 决策 |
| --- | --- | --- | --- |

## 正确性与阶段证据

观察 50 局均固定 K3/G1，**没有开启 autotune 搜索**。成功率 60%→50%，10 个布局由成功变失败、5 个反向变化。10 个退化布局全部执行 550 步并停在两块堆叠阶段，没有结果缺失或提前退出；仍无法区分时序影响与原生随机性。初始机器人状态/布局/指令相同，但全部 50 局初始 RGB 和动作摘要不同。详见 [观察对照与定位](#阶段记录异步观察单待办-50-局)。

此前三布局逐请求审计验证观察顺序、history 和动作执行一致性；独立输入/RNG 回放确认两者都能导致动作变化。50 局未保存逐请求数值/RNG，不能事后补出首次分歧。FIFO 后续仅三布局且开启 cProfile，没有同轮 FIFO1 组；模型冷/热加载 412.073→4.336 s、总步数 1363→857，禁止把总耗时比 3.84× 当作 runtime 收益。

## 应用与交付
