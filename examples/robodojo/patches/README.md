# Runtime patches: apply, check, and roll back

Modify the private/shared source only through the committed patches in this directory and
`apply_runtime_patch.py`. Source revisions are pinned in `recipe.toml`, and file scopes are read directly
from the `.patch` files. In a temporary directory the tool rebuilds the before and after contents of each
patch from the pinned Git originals, then checks the target files byte for byte. It rejects partial
application, unknown changes, and wrong revisions; apply/rollback can be repeated. Files added by a patch
must not exist before it is applied. No per-file hash JSON manifest is committed.

| Patch | Purpose | Changes evaluation semantics? |
| --- | --- | --- |
| `0000-isaac51-deps.patch` | Fixes the Starlette declaration of the pinned IsaacLab to match the upstream 5.1 installer and Isaac Sim dependencies | Package metadata only; no change to simulation, model, or task |
| `0001-measurement.patch` | Opt-in JSONL timing; adds actual action count, limit, and termination fields | No change to images, actions, RNG, reset, success checks, or video |
| `0003-parallel-autotune.patch` | Run entry point with fixed layout sharding, per-evaluation reset, and reuse of the pinned SDK autotune | Concurrency changes the order of shared RNG consumption and needs a separate correctness comparison; model code unchanged |
| `0004-async-video.patch` | Optional bounded background video pipe; see its own document | Keeps frame order and encoding parameters; full output is verified separately |
| `0005-episode-count.patch` | Changes only `stack_blocks` `eval_nums` from 25 to 50 | Extends the number of single-task layouts; per-episode semantics unchanged; not a speedup |
| `0006-unpaced-render.patch` | Optional control of render wall-clock pacing, with a fixed-timestep guard | Keeps physics/camera fences; repeated comparisons showed no stable overall gain, so it stays off |
| `0007-physics-threads.patch` | Optional fixed cap on PhysX CPU worker threads, with launch argument and effect check | No change to physics parameters/backend or autotune; thread ordering can affect nondeterminism, so compare per episode |
| `0008-control-state.patch` | Reuses unrolling within one dual-arm control call and optimizes CPU state copies | No caching across physics steps; off by default; full success rate not accepted yet |

parallel is an optional experiment; see [autotune comparison](../autotune.md) for the full commands. Complete
the native/measurement comparison and the upstream two-environment reference before applying parallel.
After all processes exit, roll back parallel first, then measurement. parallel and measurement modify
different files; every run checks the full file state of both patches. The main `run_eval.py` refuses to
run with the parallel patch applied, so a sharded experiment is not recorded as the native baseline by
mistake.

## Isaac Sim 5.1 main path

1. `prepare.py sources/assets/model/verify` prepares and verifies the original inputs.
2. Apply `isaac51-deps`, then install the simulator/model environments.
3. `prepare_runtime_assets.py apply` calls the upstream path generator. The tool backs up the original robot
   YAML to the external `ROOT/../evidence/runtime-assets/`, checks the generated bytes, and supports rollback.
4. Apply `episode-count` to declare the 50-episode scope. After the render preflight passes, run the native
   entry point with measurement in its **before** state.
5. Apply measurement, run the measured entry point with exactly the same settings, and compare.

```bash
PYTHON=/path/to/python3.11
RECIPE=/path/to/roboscope-kit/examples/robodojo
BASE=/path/to/robodojo
ROOT="$BASE/RoboDojo"

"$PYTHON" "$RECIPE/apply_runtime_patch.py" apply "$ROOT" --patch isaac51-deps
"$PYTHON" "$RECIPE/apply_runtime_patch.py" check "$ROOT" --patch isaac51-deps # after
"$PYTHON" "$RECIPE/apply_runtime_patch.py" apply "$ROOT" --patch episode-count
"$PYTHON" "$RECIPE/apply_runtime_patch.py" check "$ROOT" --patch episode-count # after
"$PYTHON" "$RECIPE/apply_runtime_patch.py" check "$ROOT" --patch measurement # before
# Here, install the environments, generate paths, run the render preflight, and run the native sample as in the main README.
"$PYTHON" "$RECIPE/apply_runtime_patch.py" apply "$ROOT" --patch measurement
"$PYTHON" "$RECIPE/apply_runtime_patch.py" check "$ROOT" --patch measurement # after
```

`episode-count` modifies different files from the other patches and stays in the same state across all
native, measured, and candidate runs. Upstream `EVAL_NUM` uses `min(requested value, task limit)`, so the
environment variable alone cannot extend the run to 50 episodes. The current profile requires this patch
explicitly, and both the serial entry point and the existing autotune entry point check the effective limit
and the required layouts before starting the GPU. With an older profile that lacks this entry, the real
limit is still checked, so a normal exit after 25 episodes is not mistaken for a completed 50.

After a dependency patch changes, rebuild the editable package metadata of the affected private environment
as described in the main recipe and pass `pip check`. Package-uninstall fixes for older environments are
neither committed nor run automatically.

## Timing

measurement records model import/loading, SimulationApp, scene initialization, per-episode reset/execution,
and model server calls. Timings include host-side waiting; this is not a CUDA kernel profiler. The first
inference warmup is part of the execution phase and is visible in the first action-call timing. The
per-episode action count includes only actions actually executed, not unconsumed predictions or physics
substeps.

GPU is sampled every 500 ms. Total wall clock includes model startup, simulator startup, evaluation, and
child-process shutdown. The formal window runs from evaluation_start to evaluation_end and includes reset,
step execution, and result output inside the window. Sub-phases can nest and cannot be summed. JSONL is
written first to the local `--metrics-root` and archived to the shared evidence directory at the end; the
archiving time is listed separately. Preparation, download, and installation are not counted in the
evaluation wall clock.

## Rollback

For applying, explicitly comparing, and rolling back the CPU worker-thread candidate, see
[physics threads](../physics-threads.md). It modifies different files from measurement; after the run exits,
roll back the candidate first, then the measurement patch.

There is also an off-by-default [video writing experiment](../async-video.md), owned by
`0004-async-video.patch`. Apply it only in a separate candidate checkout, never during a baseline run; its
file scope is separate from the other patches. See that document for commands and reverse-order rollback.

After all evaluation processes exit, roll back in reverse order. Do not delete the external backups.

```bash
"$PYTHON" "$RECIPE/apply_runtime_patch.py" rollback "$ROOT" --patch measurement
"$PYTHON" "$RECIPE/apply_runtime_patch.py" check "$ROOT" --patch measurement # before
"$PYTHON" "$RECIPE/apply_runtime_patch.py" rollback "$ROOT" --patch episode-count
"$PYTHON" "$RECIPE/apply_runtime_patch.py" check "$ROOT" --patch episode-count # before
"$PYTHON" "$RECIPE/prepare_runtime_assets.py" rollback "$ROOT"
"$PYTHON" "$RECIPE/prepare_runtime_assets.py" check "$ROOT" # before
"$PYTHON" "$RECIPE/apply_runtime_patch.py" rollback "$ROOT" --patch isaac51-deps
"$PYTHON" "$RECIPE/apply_runtime_patch.py" check "$ROOT" --patch isaac51-deps # before
"$PYTHON" "$RECIPE/prepare.py" verify "$ROOT"
```

After rolling back the dependency metadata patch, if you keep using the same environment, rebuild the
affected package metadata; the original upstream Starlette conflict comes back. Either keep or delete the
whole private environment; rolled-back source combined with old metadata is not a valid acceptance
environment.

Do not use a forced reset or bypass the content checks on unknown changes. Preserve the current state first,
then prepare again from the pinned source in a new directory. Patches, required run configuration, and tools
belong in the repository; logs, JSONL, videos, installers, and source working directories are experiment
material kept outside it.

Before updating this tool, roll back the applied patches with the old version; after updating, apply them
again in the order above. A later cleanup changed the tool to read file scopes from the patches instead of
a checksum manifest; the earlier experimental results correspond to earlier revisions of the tools. For the
changes to the multi-replica entry point and how to apply them, see [autotune comparison](../autotune.md).

## Further runtime candidates

- `0008-control-state.patch`: owner name `control-state`. Within one dual-arm control call it shares the
  unrolled result and avoids repeated copies of CPU state; [apply and roll back](../control-state.md). Each
  physics step still reads fresh state; off by default.
- `0003-parallel-autotune.patch` also contains an off-by-default observation receipt wait/FIFO. Each
  connection keeps a single in-flight RPC, and the global model lock and history semantics are preserved;
  [switches, checks, and rollback](../observation-runtime.md). It does not change model forward or RNG stream
  allocation and does not rewrite the SDK autotune.
- `0001-measurement.patch` adds itemized timing for lock waits, executor dispatch, method bodies, and return
  loops, plus an explicitly enabled causal trace. Diagnostics only; not counted as a speedup.

When upgrading, first roll back parallel and then measurement with the original version of the tool, confirm
`before`, and apply the new version. Other candidates are applied and rolled back independently in reverse
order; do not stack unverified combinations. Operate only after all related processes exit. Earlier
comparisons are interpreted against the revisions used at the time; the current patches do not stand in for
the original historical bytes.

Required input configuration is TOML. Patch scopes and digests are computed by the tool from the committed
diffs and the pinned source; no derived JSON manifest is committed. Raw outputs are not part of the
repository.
