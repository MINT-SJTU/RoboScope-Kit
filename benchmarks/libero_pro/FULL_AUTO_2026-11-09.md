# LIBERO-Pro full autotuned comparison, 2026-11-09

The complete comparison for [issue #21](https://github.com/MINT-SJTU/RoboScope-Kit/issues/21)
finished at 10:03 China Standard Time on 2026-11-09. One run of each arm completed all 16 released
single-perturbation suites: 10 tasks × 50 episodes per suite, or 8,000 episodes per arm. The
optimized arm's formal evaluation throughput was **1.3791x** the baseline, below the 2x target.
This is a single sequential matrix pair, not evidence of repeatability or correctness equivalence.
See the [fixed-baseline report](FIXED_BASELINE_2026-11-09.md) for the later #19-style run and why its
comparison against this optimized arm uses different concurrency and thread settings.

## Completeness and correctness

An independent read of the 32 formal `queue/completed` directories verified each expected suite,
task and episode index exactly once, reconciled each suite's successes and executed steps with
`result.json`, and checked all 160 per-task scores per arm against their episode records. Both arms
have matching task catalogs, seed, horizons and Policy I/O contract. All 32 Quick Tests and 32 formal
subprocesses exited successfully; formal recovery recorded zero Worker failures and zero
OOMs. Every optimized formal WorkResult reported MessagePack, camera gating on and persistent
connections off. These checks establish recorded coverage, not identical initial scenes: Worker
assignment can change task-environment reset history.

Across the paired records, 331 success flags differed: 181 successes became failures and 150 failures
became successes. Step counts differed for 3,051 pairs. These are counts of discrepancies, not an
official pooled success score. The five largest observed task-level decreases were each 5/50: goal
object tasks 0 and 6, spatial language task 4, and `libero_10` object task 3 and task-perturbation
task 8. Such differences do not identify which setting caused them, or establish a systematic
regression, without matched starts and repeated controls. The historical #19 comparison also used
different hardware and concurrency. Preserve each suite's official score separately.

Seven optimized suites selected K=8/g=1. In five, the K=16/g=2 probe exceeded the CPU-throttling
limit; in `libero_goal_object` and `libero_10_task`, it was rejected by the correctness guard. Those
two guards compared only 10 matched baseline-probe episodes: 5/10 versus 7/10 and 0/10 versus 1/10,
respectively. These small samples explain the recorded search decisions but do not prove that the
rejected configurations are unsafe or that changing the guard is justified. MPS logs include status
806 messages following explicit `terminate_client` operations during probe and server cleanup;
the formal recovery data record no failures. Do not infer a separate execution failure solely from
those cleanup messages.
